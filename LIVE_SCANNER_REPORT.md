# LIVE-сканер — 14 октября 2026

Автоматический сканер доступен на `/scanner`. Нажмите «Включить камеру» один раз: дальнейшие кадры, подтверждение, посещение и возобновление выполняются автоматически.

## Поведение

- Предпочитается задняя камера; переключение и остановка доступны во время обработки.
- По умолчанию — один JPEG-кадр каждые 600 мс, длинная сторона до 720 px, качество 0.82. Видеопоток остаётся в браузере.
- Один запрос в полёте; следующий запускается после завершения предыдущего. Сетевой таймаут 12 с, задержка повторной попытки 3 с, устаревшие ответы после остановки игнорируются.
- На сервере нужны 3 последовательных результата для одного ребёнка в пределах 5 с. Неустойчивое совпадение, отсутствие лица или несколько лиц не создают посещение.
- После подтверждения показываются фото, ФИО, группа, результат посещения и сумма только нового начисления. Пауза 2.5 с, затем автоматическое продолжение.
- Сохраняются UNIQUE(child_id, attendance_date), снимок тарифа и 15-минутный cooldown событий. Повторное распознавание никогда не создаёт второе посещение за день.
- Неизвестный снимок требует 3 последовательных похожих embeddings. Повтор похожего неизвестного лица в течение 60 с не создаёт новый файл/событие. Другое устойчиво неизвестное лицо может быть сохранено отдельно. Низкая уверенность не начисляет сумму.
- Все состояния и тексты доступны на RU / UZ / ЎЗ.

Конфигурация и допустимые диапазоны перечислены в README и `.env.example`: `LIVE_SCAN_INTERVAL_MS`, `LIVE_SCAN_STABLE_FRAMES`, `LIVE_SCAN_WINDOW_SECONDS`, `LIVE_SCAN_PAUSE_MS`, `LIVE_UNKNOWN_COOLDOWN_SECONDS`, `LIVE_UNKNOWN_SIMILARITY`.

## Сервер и данные

Миграция `c32a91df087e_live_scanner_state.py` применена к рабочей PostgreSQL. Добавлена `live_scanner_states`, связанная с `admin_sessions` через FK ON DELETE CASCADE. Состояние ограничено одной записью на сессию; новая камера в той же сессии заменяет прежний feed. `FOR UPDATE SKIP LOCKED` исключает накопление одновременных запросов, а состояние, посещение и событие записываются одной транзакцией. Временные векторы неизвестных не попадают в эталоны детей.

Резервная копия: `instance/backups/before-live-20261014T014927Z.dump`, права 0600. Контрольная проверка подтвердила, что содержимое всех прежних таблиц не изменилось. `flask --app app db check` не обнаруживает новых операций. Приложение перезапущено на http://127.0.0.1:5001; страница входа возвращает HTTP 200.

## Проверки и ограничения

Полный набор: **108 passed, 104.57 s**. После компактной мобильной компоновки: **5 браузерных тестов passed, 40.18 s**. Проверены реальные PostgreSQL/YuNet/SFace в E2E, устойчивое совпадение и сброс кандидата, отсутствие ранних начислений, повтор/пауза/возобновление, неизвестные лица и cooldown, конкуренция, rollback с удалением несохранённого снимка, CSRF, владение сессией, выход, состояния детектора и liveness failure.

Chrome-тест медленной сети держит ответ более нескольких интервалов и проверяет, что запрос остаётся единственным, видео продолжает проигрываться, кадр не превышает 720 px и поздний ответ не появляется после остановки. Проверены задняя/передняя камера, отказ разрешения и мобильные/планшетные/десктопные размеры. Мобильный снимок интерфейса просмотрен визуально. Ruff и JavaScript syntax check проходят.

Физическая камера телефона не тестировалась; для доступа с телефона нужен HTTPS. Пассивный liveness по-прежнему представлен существующим интерфейсом и состоянием «недоступно»: подтверждение нескольких кадров не является защитой от показа фотографии. Cooldown неизвестных разделяется между вкладками одной Admin-сессии, но независим между отдельными входами/браузерами. Прежний `/api/scan` сохранён как однокадровый API совместимости; браузерный LIVE-сканер использует только новые `/api/live/start` и `/api/live/frame`.
