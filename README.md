# KinderTrack

Учёт детей, посещений и начислений: **Python 3.11+**, Flask, PostgreSQL, SQLAlchemy/Alembic, локальные YuNet/SFace. Одна роль и одна учётная запись — Admin. Языки: **RU | UZ | ЎЗ**, русский по умолчанию. Платежей, задолженностей и IN/OUT нет.

## Установка

Требуются PostgreSQL 14+ (проверено на PostgreSQL 14.16), Python 3.11+ (проверено на 3.11.9) и доступ к моделям OpenCV. Создайте пользователя PostgreSQL и принадлежащие ему базы `kindscan` и `kindscan_test`. Реальные пароли задавайте вне исходного кода.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade "pip>=26.2" "setuptools>=83"
pip install -r requirements.txt
cp .env.example .env
# Заполните DATABASE_URL, TEST_DATABASE_URL, SECRET_KEY.
# Для локального HTTP выставьте COOKIE_SECURE=false.
python scripts/download_models.py
flask --app app db upgrade
flask --app app create-admin
flask --app app run --host 127.0.0.1 --port 5001
```

Откройте http://127.0.0.1:5001. `create-admin` интерактивно запрашивает email и пароль длиной 12–1024 символа, сохраняет scrypt-хеш и запрещает второго администратора. Повторное создание существующей учётной записи не требуется. **В настроенной рабочей копии не перезаписывайте `.env`.**

Существующий локальный кластер этой рабочей копии находится в `instance/postgres`, порт **55432**. При необходимости после перезагрузки:

```sh
pg_ctl -D instance/postgres -l instance/postgres.log \
  -o "-p 55432 -k $(pwd)/instance/pgsocket -h 127.0.0.1" start
source .venv/bin/activate
flask --app app db upgrade
flask --app app run --host 127.0.0.1 --port 5001
```

Не запускайте второй экземпляр уже работающего кластера. Приложение не создаёт таблицы при HTTP-запросах: схема управляется миграциями. SQLite не используется; устаревший импортёр удалён. Локальные резервные копии не удаляются приложением.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Обязательный `postgresql+psycopg://USER:PASSWORD@HOST:PORT/kindscan`. Допускается `postgresql://`; спецсимволы пароля URL-кодируются. |
| `TEST_DATABASE_URL` | Отдельная тестовая база, имя должно оканчиваться на `_test`. Рабочая база для тестов запрещена. |
| `SECRET_KEY` | Стабильный случайный секрет. Генерация: `python -c "import secrets; print(secrets.token_hex(32))"`. Без переменной используется локальный `instance/session.key` с правами 0600. Для развёртывания задайте секрет в окружении. |
| `COOKIE_SECURE` | По умолчанию `true`; `false` только для локального HTTP. |
| `TRUSTED_HOSTS` | Допустимые домены через запятую, например `attendance.example.org`. Необязателен локально; задайте для развёртывания. |
| `TIMEZONE` | По умолчанию `Asia/Tashkent`; календарные сутки и отображение времени. |
| `FACE_THRESHOLD` | Минимальная косинусная схожесть SFace, по умолчанию `0.50`; это не вероятность. |
| `FACE_MARGIN` | Минимальный отрыв от другого ребёнка, по умолчанию `0.08`. |
| `REQUIRE_LIVENESS` | По умолчанию `false`; `true` отклоняет сканирование без успешного ответа liveness-провайдера. |
| `TEST_CHROME_PATH` | Только для тестов: путь к Chrome/Chromium; на macOS по умолчанию установленный Google Chrome. |

`.env` и `.env.*` исключены из Git, кроме безопасного `.env.example`. Каталоги `instance/`, модели и тестовые артефакты также не должны публиковаться. Изменения окружения требуют перезапуска приложения.

## База данных и архитектура

```text
app.py, config.py       Фабрика приложения, окружение, обработка ошибок
commands.py             create-admin, enroll-photos, check-attendance
routes/                 Тонкие HTTP-обработчики Admin
services/               Авторизация, аудит, безопасность, фото, лица, сканер,
                        посещения, статистика, локализация и liveness-интерфейс
database/models.py      PostgreSQL/SQLAlchemy-модели
migrations/             Последовательные Alembic-миграции
templates/, static/     Общий адаптивный интерфейс
translations/           ru.json, uz_lat.json, uz_cyr.json
scripts/, models/       Проверяемая загрузка и локальные ONNX-модели
tests/                  Модульные, PostgreSQL, браузерные и полные E2E-проверки
instance/               Приватные фотографии, локальная БД, секрет и резервные копии
```

Таблицы: `admins`, `admin_sessions`, `login_attempts`, `children`, `groups`, `guardians`, `photos`, `attendance`, `scans`, `unknown_faces`, `audit`, `live_scanner_states`; служебная `alembic_version`.

- `UNIQUE(child_id, attendance_date)` и блокировка строки ребёнка защищают от двойных начислений, включая одновременные запросы.
- Тариф и историческая сумма — `NUMERIC(14,2)`/Decimal. При посещении тариф копируется, последующие изменения не меняют историю.
- Важные связи защищены внешними ключами; индексы есть на ребёнке, дате посещения, времени создания/сканирования, статусе, типе действия и объекте аудита.
- Timestamp-колонки используют `TIMESTAMP WITH TIME ZONE`. Дата посещения — отдельный календарный день в `TIMEZONE`.
- Неактивный ребёнок исключён из распознавания и повторно проверяется под блокировкой перед созданием посещения. Физического удаления детей через интерфейс нет.

```sh
flask --app app db upgrade
flask --app app db check
# При будущих изменениях моделей:
flask --app app db migrate -m "Описание изменения"
```

## Группы и родители / опекуны

Раздел `/groups` позволяет создать и изменить группу, включить/выключить её и открыть список детей. Названия хранятся в PostgreSQL. При создании ребёнка группа обязательна; выбираются только активные группы. Деактивация группы не деактивирует детей и не влияет на историю посещений: существующее назначение сохраняется, новые назначения в такую группу запрещены. В списке детей есть фильтр по группе, сохраняющийся при смене периода.

Контакты хранятся только в `guardians`, со связью с ребёнком. Форма позволяет добавить до 10 родителей/опекунов и убрать лишние строки до сохранения; типы: отец, мать, бабушка, дедушка, опекун, другое. Допускается не более одного основного контакта (это дополнительно обеспечивает частичный уникальный индекс PostgreSQL). Контакт рекомендуется, но не обязателен; неполные старые контакты остаются редактируемыми. Все контакты видны в карточке ребёнка. Изменения контактов и групп записываются в аудит.

Миграция **`b21f8d907c63`** переносит `children.parent_*` в `guardians`, затем удаляет старые колонки. Тип старого контакта — «Другое», поскольку родство неизвестно. Если уже есть дети, создаётся одна редактируемая группа «Без группы (перенесено)» и назначается им; далее укажите реальные группы. В пустой базе группы не создаются автоматически. Фотографии, векторы и история не меняются. Откат миграции блокируется, если у ребёнка несколько контактов, чтобы не потерять их молча; перед любым откатом сохраняйте полный дамп БД.

## Групповые отчёты и Excel

`/groups` показывает по каждой группе общее и активное число детей, присутствующих/отсутствующих сегодня, посещения и начисления за выбранный период. Нажатие на группу открывает `/groups/<id>`: показатели, процент посещаемости и список только её детей. Доступны поиск по ФИО/ID, фильтры «все / активные / неактивные / присутствуют сегодня / отсутствуют сегодня», периоды и постраничный вывод. На телефоне список отображается карточками.

Все связи берутся из `children.group_id`. При переводе ребёнка его текущая принадлежность и групповые отчёты меняются сразу; записи `attendance`, даты и суммы не изменяются. Исторический состав групп отдельно не хранится: отчёты используют **текущую группу**, в том числе для прошлых посещений. «Отсутствуют» = все дети группы минус присутствующие; процент = присутствующие / все дети, включая неактивных. Присутствие определяется только по `attendance_date` в `Asia/Tashkent`, а не по событиям распознавания.

На `/statistics` есть выбор «Все группы» или конкретной группы, включая неактивные группы для просмотра истории. Все показатели, дневные диаграммы и предупреждение о пропущенных посещениях учитывают выбранную группу. Неизвестным лицам группа не назначается.

Кнопка **«Скачать Excel»** выгружает `/statistics/export.xlsx` с показанными датами и выбранной группой. В ссылке даты закреплены явно, поэтому наступление новых суток между просмотром и нажатием не сдвигает период. Прямой маршрут поддерживает те же `period`, `start`, `end`, `group_id`, что и статистика. Новые посещения после открытия страницы могут изменить данные к моменту скачивания; все листы одной выгрузки согласованы благодаря PostgreSQL `REPEATABLE READ`, `READ ONLY`.

Формат `.xlsx` создаётся через `openpyxl>=3.1.5,<4` (установите обновлённый `requirements.txt`). Четыре листа: «Общая статистика», «Посещения», «По детям», «По группам». Названия и подписи переводятся на выбранный RU / UZ / ЎЗ. Фотографий, родительских телефонов и отдельного необязательного листа неизвестных лиц нет. Один ряд листа посещений соответствует одному `attendance`; исторический тариф и начисление берутся из `attendance.amount`, а текущий тариф показан отдельно на листе детей. Денежные значения остаются числами с двумя знаками, даты/время — типизированными значениями в местном часовом поясе.

Заголовки выделены, первая строка закреплена, табличные листы снабжены фильтрами, ширина столбцов рассчитывается с учётом содержимого. Имена, начинающиеся с `=`, сохраняются как текст, а не Excel-формулы. Выгрузка требует Admin-сессии и не принимает пути к файлам. Итоговый файл формируется в памяти; openpyxl использует собственные временные XML-файлы при потоковой записи и удаляет их при сохранении. Файлы проекта не перезаписываются. Имя: `statistics[_group_ID]_YYYY-MM-DD_YYYY-MM-DD.xlsx`.

Новых таблиц и миграций для этих возможностей не требуется. Подробный список изменений и результаты тестирования: [GROUP_REPORTS_EXCEL.md](GROUP_REPORTS_EXCEL.md).

## Регистрация лиц и сканер

При создании или замене 1–10 фото проверяются JPEG/PNG/WebP, размер до 15 МиБ на файл, 100 МиБ на загрузку и 50 мегапикселей. Фотография поворачивается по EXIF, уменьшается до 1600 пикселей и перекодируется без метаданных. При регистрации YuNet проверяет полный кадр в сохранённом размере и уменьшенные копии до 640 и 320 пикселей по длинной стороне (без увеличения). Порог детектора остаётся 0.85. Совпадающие детекции между масштабами объединяются; отдельные лица, включая маленькие фоновые, не игнорируются. Допускается ровно одно пригодное лицо минимум 60×60 пикселей в сохранённом изображении. Неоднозначная геометрия или размытие требуют повторной загрузки другого чёткого фото. Нейтральное выражение лица не требуется. SFace выравнивает лицо на сохранённом изображении и сохраняет нормированный 128-мерный float32-вектор (512 байт) и версию модели в `photos`.

Диагностика регистрации (`photo_preprocessing`, `registration_detection`, `registration_detection_result`, `registration_quality`) записывается на уровне INFO: размеры, EXIF-ориентация, этапы обработки, версия OpenCV/детектора, количество лиц, уверенность, координаты рамок в сохранённом изображении и резкость. Изображения, имена файлов, произвольные EXIF-поля, ключевые точки и биометрические векторы не записываются. Нулевая детекция, несколько лиц и неоднозначное/нечёткое фото имеют разные сообщения. Повторная загрузка проходит все проверки заново. Пороги сравнения личности и обработка кадров сканера не меняются.

Файлы имеют случайные имена и права 0600, каталог — 0700. Путь проверяется централизованно, обход каталога и симлинки запрещены. Фото доступны только через `/media/<id>` и `/unknown/media/<id>` после авторизации; `instance/` не раздаётся.

Редактирование полей без загрузки сохраняет фотографии и векторы. Новые фото добавляются к набору; удаляются только явно отмеченные фотографии. Изменения применяются после проверки всех файлов и сохранения данных. Ошибка откатывает изменения и очищает новые файлы.

Для старых фотографий без embeddings:

```sh
flask --app app enroll-photos
```

Команда не меняет изображения и готовые векторы. Некорректные старые снимки сохраняются для ручной замены; выводятся их ID и код причины. Загрузчик моделей проверяет SHA-256. Все вычисления выполняются локально; при сканировании сравниваются сохранённые векторы, а не фотографии всей базы. Проверено сравнение 1500 векторов для 500 детей.

На `/scanner`: один раз включите камеру и держите лицо в рамке несколько секунд. Ручного захвата для каждого ребёнка больше нет: LIVE-распознавание работает автоматически. Предпочитается задняя камера, доступны переключение и остановка; при уходе со страницы камера выключается. Моргать, улыбаться или поворачивать голову не нужно. Для телефона необходим **доверенный HTTPS**; localhost работает на компьютере, где открыт браузер, но HTTP по IP-адресу компьютера для телефона обычно не подходит.

Первый уверенный скан создаёт посещение; повторный в тот же день показывает «Ребёнок уже отмечен сегодня». 15-минутный cooldown подавляет повторные события сканера, но никогда не разрешает повторное начисление в тот же день. В новый календарный день посещение допускается сразу. Неуверенные и неоднозначные совпадения сохраняются как неизвестные снимки с временем, сходством и причиной; они не создают посещений.

### Непрерывное LIVE-распознавание

Браузер сохраняет видеопоток активным, раз в 600 мс берёт JPEG-кадр с длинной стороной не более 720 px (качество 0.82) и отправляет его на `/api/live/frame`. В каждый момент выполняется максимум один запрос: медленный ответ уменьшает частоту, очередь кадров не создаётся. Таймаут — 12 секунд, после сетевой ошибки — пауза 3 секунды. Во время обработки можно остановить или переключить камеру; старые ответы игнорируются. При уходе/скрытии страницы камера и таймеры отключаются.

По умолчанию сервер требует 3 последовательных совпадения одного ребёнка в пределах 5 секунд. При редкой выборке окно автоматически расширяется для подтверждения. Другое лицо, отсутствие лица или истечение окна сбрасывает подтверждение. После подтверждения используются существующие правила посещений. Фото, ФИО, группа, результат и сумма нового начисления показываются 2.5 секунды; затем обработка возобновляется, без выключения камеры. Уже отмеченный ребёнок не получает повторного посещения/суммы.

Неизвестное лицо тоже требует последовательного подтверждения; SFace-векторы кадров сравниваются, чтобы не объединять разных неизвестных людей. Для похожего неизвестного лица действует cooldown 60 секунд в рамках Admin-сессии, включая переключение/перезапуск камеры. Другое устойчиво неизвестное лицо можно сохранить сразу после короткой паузы. Низкая уверенность никогда не создаёт посещение.

| Переменная | По умолчанию | Допустимый диапазон |
| --- | --- | --- |
| `LIVE_SCAN_INTERVAL_MS` | `600` | 300–5000 мс |
| `LIVE_SCAN_STABLE_FRAMES` | `3` | 2–3 результата |
| `LIVE_SCAN_WINDOW_SECONDS` | `5` | 2–15 секунд |
| `LIVE_SCAN_PAUSE_MS` | `2500` | 2000–3000 мс |
| `LIVE_UNKNOWN_COOLDOWN_SECONDS` | `60` | 10–300 секунд |
| `LIVE_UNKNOWN_SIMILARITY` | `0.65` | 0.30–0.95, косинусная схожесть |

Значения ограничиваются указанными диапазонами. После изменения окружения перезапустите приложение. Более длинное окно подтверждения может понадобиться при медленной сети.

Миграция `c32a91df087e` добавляет `live_scanner_states`: одна ограниченная запись на Admin-сессию, FK на `admin_sessions`, JSONB-состояние и индекс времени. Блокировка PostgreSQL `FOR UPDATE SKIP LOCKED` не даёт одновременным запросам накапливать подтверждения. Состояние, посещение и событие сканирования фиксируются одной транзакцией. Новый запуск камеры создаёт новый feed ID и останавливает прежний feed той же сессии (например, в другой вкладке).

Кратковременный кеш неизвестных содержит до 32 векторов; просроченные элементы удаляются при следующем кадре/запуске. Состояние, не обновлявшееся 15 минут, не принимается и очищается при запуске сканера; выход удаляет запись каскадно. Отдельные Admin-сессии имеют независимые cooldown-кеши. Векторы этого кеша не добавляются к эталонам детей. История существующих посещений и фото миграцией не меняется.

Новые браузерные страницы используют только `/api/live/start` и `/api/live/frame`. Прежний защищённый `/api/scan` сохранён для совместимости как однокадровый API; автоматический сканер его не вызывает.

**Пассивная защита от фотографии/экрана пока не реализована.** `LivenessProvider.check(image, face)` — интерфейс для проверенного провайдера; поставляемый `UnavailableLiveness` явно возвращает `unavailable`. Сканер сообщает об этом и рассчитан на работу под наблюдением администратора. Отказ провайдера или `REQUIRE_LIVENESS=true` без провайдера блокируют результат.

## Отчёты, аудит и языки

Главная содержит шесть показателей, реальные дневные диаграммы, последние сканы, недавно распознанных детей и неизвестные снимки. Статистика показывает уникальных детей, посещения, сумму и среднее за **все календарные дни периода**, включая нулевые дни. Есть таблица точных дневных значений.

Периоды: сегодня, вчера, 7/30 дней, текущий месяц/год до сегодняшнего дня, предыдущий месяц и произвольный диапазон до 731 дня. Для неизвестных лиц и аудита — сегодня, 7/30 дней и произвольный диапазон. Аудит дополнительно фильтруется по действию. Все отчёты читают PostgreSQL; демонстрационных данных в приложении нет.

Аудит хранит ID, действие, объект и его ID, старое/новое значение, детали, Admin и время. Записываются вход/выход, создание/редактирование, активация/деактивация, тариф, замена фотографий и важные ошибки. Успешные изменения и соответствующий аудит сохраняются одной транзакцией. Ошибки используют только фиксированные коды, без паролей, токенов, строк подключения и содержимого снимков. При недоступной БД событие невозможно записать в PostgreSQL: приложение возвращает безопасный 503, а в системный лог пишет только категорию ошибки.

UI использует ровно три централизованных JSON-каталога: русский, узбекский латиницей и кириллицей. Язык сохраняется в подписанной сессии; отдельных страниц для языков нет. Имена пользователей/детей остаются исходными данными, а не переводятся. Служебные команды CLI и имена технических параметров могут быть на английском.

### Диагностика распознаваний без посещений

```sh
flask --app app check-attendance
```

Команда только читает БД и перечисляет события `recognized` / `success` / `already`, для которых нет посещения ребёнка в соответствующий календарный день `Asia/Tashkent`. Дашборд и статистика показывают предупреждение о таких событиях за выбранный период. Они не превращаются в начисления автоматически: исторический тариф нельзя выводить из текущего.

Проверка рабочей базы 13–14 октября 2026 выявила **6 старых событий `recognized` за 13 октября для двух детей и 0 посещений**. Текущий сервис сканирования уже создаёт посещение и событие `success` одной транзакцией. Проверка подтвердила, что старое событие внутри cooldown не блокирует первое реальное посещение. Подробности, точные запросы, миграция и список изменений: [GROUPS_STATISTICS_REPORT.md](GROUPS_STATISTICS_REPORT.md).

## Безопасность

Защищённые страницы, API и оба типа фотографий требуют действующей Admin-сессии. Пароли — scrypt; сессия ограничена восемью часами и отзывается в PostgreSQL при выходе. Cookie — HttpOnly, SameSite=Lax и Secure для HTTPS. CSRF обязателен на всех изменяющих запросах; после входа токен обновляется. Есть ограничение попыток входа, ограничения форм/файлов, экранирование шаблонов, параметризованные ORM-запросы, CSP, запрет iframe, no-store для приватных ответов и HSTS на HTTPS.

Для эксплуатации используйте production WSGI-сервер за HTTPS-прокси, `COOKIE_SECURE=true`, `TRUSTED_HOSTS` и отдельного пользователя БД. Не публикуйте Flask development server или каталог `instance/`. Регулярно сохраняйте `pg_dump` и приватные фото; проверяйте восстановление вместе с секретом сессии. Автоматическая очистка старых снимков/аудита пока не настроена.

## Тестирование

```sh
pip install -r requirements-dev.txt
python -m pytest -q
flask --app app db check
ruff check app.py config.py commands.py database routes services scripts tests --select F401,F841,F821
pip-audit --local
python -m compileall -q app.py config.py commands.py database routes services
```

Основной набор требует `TEST_DATABASE_URL` и создаёт отдельную временную схему на тест; рабочие данные не очищаются. `tests/test_end_to_end.py` самостоятельно запускает новый временный PostgreSQL-кластер через `initdb`/`pg_ctl`, создаёт базу и Admin, поднимает Flask и проходит весь пользовательский путь в настоящем Chrome. Для этого теста нужны локальные PostgreSQL-утилиты, Chrome и скачанные модели. При отсутствии необходимых браузерных зависимостей соответствующие тесты явно пропускаются.

E2E: вход → группа → ребёнок/отец и мать → три фото и embeddings → редактирование/тариф/фото → мобильный скан → одно посещение и снимок тарифа → повтор → неизвестное лицо → отчёты/фильтры → RU/UZ/ЎЗ → статусы → аудит → ширины 390/768/1440 → выход и запрет защищённых страниц. Камера подаёт записанные тестовые кадры, **без доступа к физической камере**; распознавание, HTTP и PostgreSQL не подменяются. Более быстрые тесты изолируют отдельные компоненты с mock-векторами; реальные модели проверяются отдельно.

Проверяются также неверный пароль, CSRF, отозванные cookie, некорректные/пустые/многолицевые изображения, отказ/отсутствие камеры, низкая уверенность, отказ liveness, неактивный ребёнок, конкуренция, UNIQUE, смена суток/тарифа, обязательные поля, traversal/симлинки, ошибка PostgreSQL и отсутствие утечек секретов.

Остаются ручная проверка настоящих камер iOS/Safari и Android через HTTPS, оценка точности на репрезентативной выборке детей и настройка проверенного пассивного liveness. Тестовые взрослые портреты подтверждают работоспособность кода, а не точность на детях. Развёртывание production HTTPS и восстановление из резервной копии должны быть проверены в целевом окружении.

Звуки LIVE-сканера: локальный `static/audio/applepay.mp3` для нового посещения и `static/audio/error_CDOxCYm.mp3` для подтверждённого неизвестного лица. Оба файла предварительно загружаются и декодируются через Web Audio при запуске сканера. Повторное посещение и системная ошибка имеют отдельные синтезированные сигналы. При недоступном MP3 используется короткий синтезированный сигнал без задержки распознавания. Кнопка «Звук» сохраняет настройку в localStorage; по умолчанию включена. Аудио разблокируется нажатием запуска камеры или включения звука. Повтор одного результата для того же ребёнка подавляется на 15 минут в открытой странице; ошибки — на 15 секунд. Обычные поисковые кадры беззвучны. Если браузер блокирует аудио, сканер продолжает работу.

Неизвестные лица: доступны удаление одного снимка, выбранных снимков на текущей странице и очистка всех снимков старше 7/30/90 суток либо за включительный диапазон местных дат (Asia/Tashkent). Все операции требуют Admin, CSRF и подтверждения; действия записываются в аудит. Удаляются только `unknown_faces` и их файлы, сканирования и посещения сохраняются. Сервис проверяет закрытый путь, запрещает симлинки и совпадение с именем фотографии ребёнка. Отсутствующий файл не мешает удалению записи. Временные закрытые жёсткие ссылки позволяют восстановить файлы при обычной ошибке транзакции/удаления и удаляются после успеха. PostgreSQL и файловая система не образуют единую атомарную транзакцию: после аварийного завершения процесса нужно проверить оставшиеся каталоги `.unknown-delete-*` в закрытом хранилище. Тесты: `tests/test_unknown_deletion.py`, `tests/test_unknown_deletion_browser.py`.

### Reference photos and mobile LIVE scanner (October 2026)

Registration accepts 1–10 references per child: JPEG/PNG/WebP, 15 MiB per
file, 100 MiB total per submitted batch, and 50 million source pixels. Animated,
corrupt, unsupported and oversized images are rejected before enrollment. Photos
are decoded, EXIF-oriented, stripped of metadata and resized proportionally to
1600 px maximum edge (JPEG quality 90). Use several useful facial angles.
New uploads **append**; check an existing photo for removal and add a new one to
replace it. At least one reference must remain. Only added references are embedded;
profile edits do not regenerate or delete vectors. Each photo has its own PostgreSQL
embedding associated with its child. Recognition reads vectors, never reference images.

Private files remain behind authenticated `/media` routes with `no-store` responses,
0700 directories and 0600 files. `DATA_DIR` and `MODEL_DIR` accept absolute paths.
Local development defaults remain `instance` and `models` in the project.

For Railway, attach a persistent volume at `/data` and set the service start command
to `sh scripts/start_railway.sh`. Configure the existing PostgreSQL `DATABASE_URL`,
`SECRET_KEY`, HTTPS/cookie and trusted-host settings. The start script installs or
verifies models **on the volume at runtime**, applies existing migrations and starts
Gunicorn. Do not download models into a volume during build or pre-deploy:
[Railway mounts volumes only at runtime](https://docs.railway.com/volumes).
Startup refuses Railway paths outside the configured volume. Before switching an
existing deployment, copy its private `photos` directory into `/data/photos`, preserving
filenames and permissions; retain the existing database and secret. Back up both the
volume and PostgreSQL. Verify a stored photo and model checksums before and after a
redeploy. An attached volume and actual redeployment must be verified in Railway;
local tests cannot establish deployment persistence.

LIVE sampling is configurable with `LIVE_SCAN_INTERVAL_MS` (300–5000 ms).
One request runs at a time; the source frame is resized to at most 720 px, JPEG .82.
Duplicate sample fingerprints are throttled to 1.5 seconds while confirming a
match and 10 seconds otherwise, preserving stable confirmation without repeatedly
submitting a static scene. Preview cover cropping and front
mirroring are display-only. Boxes map source coordinates using the cover scale and
center offset and are clipped to the preview; stale boxes expire. Fullscreen uses the
browser API with a CSS fallback. Existing stable recognition, database attendance
uniqueness and audio cooldowns remain in place.

Quality hints use the same backend detection pass: face/frame ratio, boundary position,
mean face luminance, Laplacian variance on a 128×128 face crop, face count, and landmark
asymmetry. Thresholds are heuristic advisory labels, not calibrated quality or identity
percentages. Side-angle hints do not block recognition; the existing minimum face size
and multiple-face safety rules remain. Hints and boxes arrive at recognition cadence,
so they can lag motion by network/inference latency. No extra camera analysis requests
are issued. Physical Android/iOS camera behavior and recognition across real child
poses require device and representative-data testing.
